# API Contract: app01

**Branch**: `001-shell-app01-wellbeing` | **Date**: 2026-04-08
**Base path**: `/api/v1`
**Auth**: All endpoints require shell middleware (valid Clerk JWT + app01 access).
**Content-Type**: `application/json` for all request/response bodies unless noted.
**Rate limiting**: Global 60 req/min per user (FR-070). Endpoint-specific stricter limits noted per endpoint. All rate-limit responses return `429 Too Many Requests` with a `Retry-After` header.

---

## Entries

### GET /api/v1/entries

Returns all entries for the authenticated user, newest first.

**Query params** (all optional):

| Param | Type | Description |
|---|---|---|
| `q` | string | Reserved for future server-side search. **In v1 this param is ignored by the server** — filtering is performed client-side on the full entry list returned by this endpoint. |

**Response 200**:
```json
[
  {
    "date": "2026-04-07",
    "moodScore": 4,
    "noteText": "Felt good today, went for a walk.",
    "createdAt": "2026-04-08T08:00:00Z",
    "updatedAt": "2026-04-08T08:05:00Z"
  }
]
```

`noteText` and `moodScore` may be `null` if the entry exists but those fields have not been set.

---

### GET /api/v1/entries/:date

Returns the entry for a specific date.

**Path param**: `date` — ISO date string `YYYY-MM-DD`

**Response 200**: Single entry object (same shape as above).

**Response 404**: No entry found for that date.

```json
{ "error": "Not found" }
```

---

### PUT /api/v1/entries/:date

Creates or updates the entry for a date. Partial updates are supported — omit a field to leave it unchanged.

**Path param**: `date` — ISO date string `YYYY-MM-DD`

**Request body** (all fields optional):
```json
{
  "moodScore": 3,
  "noteText": "Tired but productive."
}
```

Validation:
- `moodScore`: integer 1–5 or `null`
- `noteText`: string (max 5000 chars) or `null`
- `date` must not be in the future (relative to server UTC date)

**Response 200**: Updated entry object.

**Response 400**: Validation failure.
```json
{ "error": "moodScore must be between 1 and 5" }
```

**Response 422**: Date is in the future.
```json
{ "error": "Cannot create entry for a future date" }
```

## Insights

### GET /api/v1/insights

Returns the 7-day mood score series and a generated summary text.

**Rate limit**: 30 req/min per user (FR-073).

**Response 200**:
```json
{
  "days": [
    { "date": "2026-04-01", "moodScore": 3 },
    { "date": "2026-04-02", "moodScore": null },
    { "date": "2026-04-03", "moodScore": 4 },
    { "date": "2026-04-04", "moodScore": 5 },
    { "date": "2026-04-05", "moodScore": 4 },
    { "date": "2026-04-06", "moodScore": 3 },
    { "date": "2026-04-07", "moodScore": 4 }
  ],
  "summary": "Your mood has been improving — scores rose this week.",
  "hasEnoughData": true
}
```

- `days`: exactly 7 items, starting 6 days ago through yesterday (server-side UTC); `moodScore` is `null` for missing entries.
- `summary`: rule-based string generated by `app01/src/insights.ts`.
- `hasEnoughData`: `false` if fewer than 2 entries exist in the window; frontend shows encouragement message instead.

## Settings

### GET /api/v1/settings

Returns the current user's settings. Creates a default settings row if none exists.

**Response 200**:
```json
{
  "theme": "system",
  "reminderEnabled": false,
  "reminderTime": null
}
```

`theme` values: `"light"`, `"dark"`, `"system"`

---

### PUT /api/v1/settings

Updates one or more settings fields.

**Request body** (all fields optional):
```json
{
  "theme": "dark",
  "reminderEnabled": true,
  "reminderTime": "20:00"
}
```

Validation:
- `theme`: one of `"light"`, `"dark"`, `"system"`
- `reminderTime`: `HH:MM` format string or `null`; required when `reminderEnabled` is `true`

**Response 200**: Updated settings object (same shape as GET response).

**Response 400**: Validation failure.
```json
{ "error": "reminderTime is required when reminderEnabled is true" }
```

## Export

### GET /api/v1/export

Downloads the user's entries for a given date range in the requested format (FR-052, FR-053, FR-054).

**Rate limit**: 10 req/hour per user (FR-071).

**Query params**:

| Param | Type | Required | Description |
|---|---|---|---|
| `from` | `YYYY-MM-DD` | Yes | Start of date range (inclusive) |
| `to` | `YYYY-MM-DD` | Yes | End of date range (inclusive) |
| `format` | `csv` \| `pdf` | Yes | Export format |

**Response 200 — CSV** (`format=csv`):
- `Content-Type: text/csv; charset=utf-8`
- `Content-Disposition: attachment; filename="beinge-export-{from}-{to}.csv"`

```
date,score,note
2026-04-07,4,"Felt good today, went for a walk."
2026-04-06,3,Tired but productive.
```

Header row always present. Fields with commas or newlines are double-quote escaped. `score` is empty string when `moodScore` is null.

**Response 200 — PDF** (`format=pdf`):
- `Content-Type: application/pdf`
- `Content-Disposition: attachment; filename="beinge-export-{from}-{to}.pdf"`

PDF contains one entry per page section: date as heading, mood score, full note text.

**Response 400**: Missing or invalid params.
```json
{ "error": "Missing required query params: from, to, format" }
```

**Audit log emitted on success** (FR-082):
```json
{
  "event": "data_exported",
  "userId": "user_2abc123",
  "from": "2026-01-01",
  "to": "2026-04-08",
  "format": "csv",
  "timestamp": "2026-04-08T14:00:00Z"
}
```

## Account

### DELETE /api/v1/account

Permanently deletes the authenticated user's account and all their data (FR-055, FR-063).

**Rate limit**: 5 req/day per user (FR-072).

**Auth**: Required. The user deletes their own account; admins cannot use this endpoint to delete other users.

**Request body**: none required, but the frontend MUST display an explicit confirmation dialog before calling this endpoint.

**Response 204**: Account and all data deleted. No body.

**Audit log emitted** (FR-081):
```json
{
  "event": "account_deleted",
  "userId": "user_2abc123",
  "deletedRows": { "entries": 42, "userSettings": 1, "userAppAccess": 1 },
  "timestamp": "2026-04-08T14:00:00Z"
}
```

**Sequence**:
1. Delete `app01.entries` for this `userId`
2. Delete `app01.user_settings` for this `userId`
3. Delete `shell.user_app_access` rows for this `userId`
4. Call Clerk Backend API to delete the Clerk user record

Steps 1–3 are wrapped in a single DB transaction. If the Clerk deletion (step 4) fails, the server logs the error with full context; the Clerk record can be manually cleaned up by an admin.

**Response 500**: DB or Clerk error (logged server-side).
```json
{ "error": "Account deletion failed" }
```

## Error Response Format

All error responses use the same shape:

```json
{ "error": "Human-readable message" }
```

| HTTP Status | Meaning |
|-------------|---------|
| 400 | Bad request / validation failure |
| 401 | Not authenticated |
| 403 | Authenticated but no app01 access |
| 404 | Resource not found |
| 422 | Request valid but semantically rejected (e.g., future date) |
| 429 | Rate limit exceeded; `Retry-After` header indicates seconds until reset |
| 500 | Server error (logged with full context server-side) |
